# codyssey-basic-b2-2-git-team-collaboration

친구 3~5명과 함께 프로그램 만드는 법 연습하기

## GitHub Flow를 사용하는 이유

작업 단위별로 브랜치를 분리하면 `main`의 안정성을 유지하면서 변경 이유와 책임을 추적할 수 있습니다. PR과 리뷰를 통해 변경을 병합하기 전에 팀이 품질과 의도를 확인할 수 있습니다. Issue → Branch → PR → Review → Merge 기록은 협업 과정을 재현 가능한 Evidence로 남깁니다.

## 현재 상태

정적 협업 하네스는 Workcell에서 준비하지만, B2-2의 PASS는 실제 3~5인 팀의 collaborator 권한, `main` Branch Protection, 팀원별 PR/Review, 리뷰 반영, 실제 충돌·트러블슈팅, Git graph Evidence가 확인된 뒤에만 가능합니다.
